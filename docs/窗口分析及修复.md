# first.dll 窗口分析与修复

本文汇总 first.dll 自带窗口（DFM 窗体）的清单与用途、字体归属，以及窗口文本编码、
高分屏缩放两类修复；拖动相关见 4.1，退出崩溃修复见第 8 节。

---

## 1. 窗口清单与用途

DLL 通过 DFM 建 19 个窗体；可在设置窗（Tfirstconfigform）的勾选框里开关的共 6 个：
模拟时钟 + 5 项文字信息。其余为菜单/工具/游戏窗。

|---|---|---|

`等线` / `楷体` 等短名。

## 3. 窗口文本编码修复（DFM Font.Charset → GB2312_CHARSET）

DLL 是 ANSI 程序，DFM 字符串按字节交给系统，按渲染路径分两种解释：

- **TLabel 等 VCL 自绘文字**：GDI 的 ANSI 文本函数按**当前字体 charset 对应的代码页**转换字节；
- **窗口控件（TButton / TCheckBox / TTabSheet / TTreeView / TEdit 等，有 HWND）**：文案走窗口消息，
  系统按 **ACP**（本机 = 936/GBK）转换。

原版把 18/20 个窗体的 `Font.Charset` 设为 `SHIFTJIS_CHARSET`（CP932），所以这些窗体里的
TLabel 文案必须是 Shift-JIS——`translated.csv` 中原先有 12 条 rsrc 行（Tfirstconfigform /
Tnotifyform 的全部 label：うるさい ／ 黙 ／ 月 ／ 日／毎週 ／ 時 ／ 分 ／ メッセージ ／
日時 ／ 実行ファイル ／ 年 ／ 曜日 ／ 喋る頻度(&A)）靠 `SHIFTJIS_OFFSETS` 特判保持 SJIS，
译文只能用 SJIS 允许的字符。唯一未设 charset 的 Tversionforms，其 label（beveltitlelabel）
本来就按 ACP 走，GBK 无碍。

现由 `patch_dll.py` 的 `patch_dfm_charset()` 把这两个窗体的 `Font.Charset` 改为
`GB2312_CHARSET`（值编码 `07 10 "SHIFTJIS_CHARSET"` → `07 0E "GB2312_CHARSET"`；
值之后到本窗体数据块末尾的内容整体左移 2 字节、块尾补 0，资源大小与后续资源位置不变；
**必须在文本翻译写入之后执行**，翻译随区块一起平移、DFM 结构保持自洽）。改后这两个
窗体的 label 文案按 CP936 解释，随大流使用 GBK；`SHIFTJIS_OFFSETS` 已清空，那 12 行
译文可改用任意 GBK 汉字。其余 16 个窗体保持 `SHIFTJIS_CHARSET` 不变（其中没有
需要翻译的 label 文案）。

## 4. 高分屏缩放（load/request 导出包装 + UNAWARE_GDISCALED）

**问题**：所有 DFM 窗体 `Scaled = False`、`PixelsPerInch = 96`；SSP 是 DPI 感知进程，
系统不做位图拉伸，于是 DLL 自建窗口在 150%/200% 屏上仍然只有 96dpi 大小。

**方案（现行）**：不动 API 导入/跳板，把 DLL 的 `load` / `request` 两个导出入口改指向
`.cave` 包装桩：调用真实函数**之前**把当前线程 DPI 上下文切到
`UNAWARE_GDISCALED(-5)`，**之后**还原。于是装载/请求期间创建的窗口（含窗口控件与
FormPaint 自绘文字）全部被系统按屏幕缩放且清晰（GDI 缩放）；请求之外 SSP 自己的界面
不受影响。

实现要点（`patch_dpi_wrap()`）：

- 只改 PE 导出表两个 RVA（`load` / `request` → `.cave+0x1F7C` / `.cave+0x170`）；
- 桩为位置无关代码，全部状态在栈上（可重入）；`SetThreadDpiAwarenessContext` 指针惰性解析
  （`GetModuleHandleA("user32.dll")` + `GetProcAddress`，IAT 槽 0x4B31E4 / 0x4B31E0），
  数据（PSET 指针 + 字符串）放 `.cave+0xB0`；
- 导出是「调用方清栈」（函数末尾裸 `ret`），桩也以裸 `ret` 返回；调用真实函数后由桩
  `add esp,8` 清掉自压实参副本；
- 总开关 `DPI_WRAP_ENABLE`。

**互斥方案**：DFM `Scaled=False → True`（`patch_dfm_scaled()`，由 `DFM_SCALED_ENABLE`
控制，默认关闭）。VCL 会按屏幕 DPI 放大一次，与导出包装叠加会双重放大；且该方案覆盖不了
自绘文字。

### 4.1 拖动相关的 SendMessage 包装

信息窗拖动 = 窗体 `FormMouseMove` 事件（按住左键移动）里
`ReleaseCapture()` + `SendMessage(WM_SYSCOMMAND, SC_DRAGMOVE=0xF012, MAKELPARAM(X,Y))`。
共 6 处（0x46326D / 0x46755E / 0x468C56 / 0x46D615 / 0x46EC75 / 0x4704DE，对应 6 个
窗体类）。`patch_dpi_drag()` 把这 6 个 `SendMessageA` 调用改指向 `.cave+0x2000` 的包装桩：
调用期间（含整个拖动模态循环）线程置 GDISCALED、返回后还原，形参 4 个 dword、`ret 16`。

### 4.2 .cave 布局（含高分屏部分）

```
0x00B0  高分屏数据：PSET / "user32.dll" / "SetThreadDpiAwarenessContext"
0x0170  request 包装桩（临时模式）        0x1F7C  load 包装桩（临时模式）
0x2000  拖动包装桩（SC_DRAGMOVE 的 SendMessageA）
0x2200  系统字体初始化包装桩（见 4.3）    0x22C0  TStatusBar CS_HREDRAW 透明桩
0x226A  退出修复：收尾例程                0x23F4  退出修复：上下文暂存槽
0x2400  退出修复：存根                    0x2640  退出修复：归还桩（V7）
0x2700  退出修复：入口跳板（V7；见第 8 节） 0x2810..0x5DC0  输入法修复段（见第 9 节）
0x7500  退出修复：枚举回调                0x7600  类名缓冲
0x7700  ULW 上屏桩（命中掩码 + 跨 100% 刷新安装/解除；见 §6/§10）
```

节大小 **0x8000**。其余偏移（游戏/重力语桩与表等）见

### 4.3 系统字体初始化包装（Todo/Notify 状态栏提示字缩放修复）

**问题**：Todo / Notify 窗口底部状态栏提示文字（"信息"）在缩放后过大。

**根因**：状态栏字体不是窗体字体，而是**系统消息字体**（`Microsoft YaHei UI`），由
`SystemParametersInfo(SPI_GETNONCLIENTMETRICS)` 在**线程 DPI 感知时**取得（144dpi 规格
→ h=-18），放进被系统虚拟化的窗口里又放大一次。字体初始化函数 0x44E024 只在
0x44D946 / 0x44EEED 两处被调用（无间接引用）。

**方案（`patch_dpi_sysfont()`）**：把这两处调用改指向 `.cave+0x2200` 包装桩：调用期间线程
置 `UNAWARE_GDISCALED` → 取到 96dpi 规格（h=-12），恢复后原样返回；与窗口里其它控件一致。

**已放弃**：给窗口类补 `CS_HREDRAW`（修状态栏 resize 重影，见第 7 节）。

## 6. 透明窗命中判定修复（first.dll 的 ULW 命中掩码）

**现象**：文字信息窗（Tcpuloadform）只有部分文字能点/能拖，模拟时钟（Tanalogclockform）
几乎全盘不可点；显示与命中区错位、鼠标经过时命中时有时无；100% 缩放下一切正常。

**根因**：这两个监控窗是 `WS_EX_LAYERED` + `UpdateLayeredWindow` 逐像素 alpha 窗口，
**系统做鼠标命中判定时看的是图层 alpha**（alpha==0 穿透、alpha>0 算点中本窗）。
100% 时系统"鼠标在哪读哪"，图层 alpha 即命中形状 → 精确；DPI 虚拟化（≠100%）时
系统的命中采样坐标被放大：**实测（合成标记盒标定）鼠标在显示坐标 V 处读图层 V/2 处、
偏移为 0（真实坐标），即"命中形状 = 图层放大 2 倍"，与显示的 1.5× 不一致** →
可见像素点不中（红色）、空白处出现幽灵命中区（蓝色）。此为 Windows 行为，只能反向校正。

**修复（`patch_ulw_hitmask`，全部在 first.dll）**：

1. 4 处 ULW 调用点（VA 0x462C90/0x462CB8/0x462D2A/0x462D50，原 9 字节
   `mov eax,[表]; mov eax,[eax]; call eax`）替换为 `call .cave 前置桩` + 4×NOP。
   桩每次上屏前运行：
   - `GetCurrentObject(hdcSrc, OBJ_BITMAP=7)` + `GetObjectA(hbmp,84,&ds)` 取图层位图；
   - 仅处理：bpp=32 且窗口类名为 Tanalogclockform/Tcpuloadform（GetClassNameA 比对）；
   - DPI 因子采样：线程 PMv2 → GetWindowRect 取物理宽，恢复上下文；
   - **=100%（物理宽==图层宽）：不做任何修改，直通（与未打补丁的原版行为一致）**；
   - **≠100%：写命中掩码** `掩码[U,·] = 内容[2U,·]`——对每个内容像素（RGB≠0 或
     alpha≥2）取 `U=x>>1`、`Vd=y>>1`（显示坐标缩半），行号按 DIB 自底向上翻转回内存，
     只把目标像素中 alpha==0 的置为 1（1/255 不可见）；不加任何膨胀余量；
   - `popad` 后**重新锚定**再尾跳真实 ULW（表项→槽两级间接）。
2. misaki.dll 保持原版不动（构建不再产出/部署 misaki）；跨 100% 缩放刷新修复已并入
   first.dll 本层（见 §10）。

**构建期关键点（必读）**：
- 4 个调用点的原操作数带 **PE HIGHLOW 重定位项**，补丁替换后**必须从 .reloc 删除
  对应条目并更新目录大小**，否则加载器把 rebase 差值加到补丁字节上 → 调用乱飞
  （曾实测：`[SYSTEM] Exception Raised at <基址+0xE9700>`、监控窗不创建）。
  构建器已自动删除并断言数量=4。
- 桩内 `popad` 会恢复 EBX（PIC 基址）→ 尾跳前必须重新锚定。
- `_EXF_IAT_*` 常量是 **RVA**，使用需 +0x400000。
- 图层 DIB 是**自底向上**存储：任何"显示坐标"处理都要做行号翻转（`H−1−y`）。
  早期拟合曾因漏掉翻转得出"每窗不同偏移"的假象。
- 拟合/配对要按"预测位置最近"匹配（曾因错配整盒得出 2x−12.5 的假规律）。

**验证**（`_re_tmp/hitvis.py`：冻结进程，读图层并逐点 WindowFromPoint 扫描，叠加
绿=命中且内容/红=内容未命中/蓝=命中无内容）：≠100% 下两窗均 **红=0**（每个可见像素
100% 可命中）；100% 下不做任何修改。

**历史（已删除/已放弃，勿再走）**：
- misaki 整层填 0x01 + 信息窗高度 0x80→0x40 的旧方案（命中区=整窗，不精确）——已从
  代码与注释中彻底删除；
- `WM_NCHITTEST` 精准判定方案（整层填充当门闸 + 窗口自查掩码）：实现完整、实验台通过，
  但接入后 SSP 启动必崩在 `first.dll+0x3AF2`（应用自身对象拷贝，ESI=0，3/3 复现），
  无法落地；
- 内容包围盒（bbox）备选、逐像素"按 1.5 压缩"等中间方案：均已被上述最终实现取代；
- 在绘制路径上挂钩（改 allclear 边界、SetWindowRgn 等）：历史上导致启动崩溃。

## 7. Todo/Notify 状态栏改大小后文字重影（已修复：CreateParams 补 CS_HREDRAW）

- **现象**：拖动改变 Todo / Notify 窗口大小后，底部状态栏提示文字（"信息"）出现
  重影/发虚，重开窗口才恢复。**原版（未打补丁）同样存在**；实测外部强制
  `RedrawWindow` 一次即恢复，说明是"旧像素未擦除"。
- **根因**：VCL 给 `TStatusBar` 注册的窗口类样式 = `CS_VREDRAW | CS_DBLCLKS`（**缺
  `CS_HREDRAW`**，实测读数 0x9）→ 改变宽度时系统不做整窗失效 → 状态栏不整体重绘。
  跨进程 `SetClassLong` 改不了（写后读回仍是 0x9）。
- **修复**：在 `TWinControl.CreateWnd`（0x435294）调用虚拟方法 `CreateParams` 的指令处
  `0x4352C1`（`call [ecx+0x90]`；调用前 `mov ecx,[eax]`，`eax`=控件对象、`ebp`=CreateWnd
  栈帧）改为 `call` 到 `.cave+0x22C0` 的透明桩：
  1. 补完原 `call [ecx+0x90]`；
  2. 比较栈帧里正在填充的 `Params` 的类名缓冲（`[ebp-0x40]`/`[ebp-0x3C]`）是否为
     `"TSta"`/`"tusB"`（即 `TStatusBar`）；
  3. 命中才 `or dword [ebp-0x68], 2`（`WindowClass.style |= CS_HREDRAW`），随后 `ret`。

  其余窗口类完全透明（只多两条比较）。**不碰 `RegisterClassA` / 类注册 / 退出流程。**
- **效果**：Todo / Notify 拖动改大小后状态栏即时整体重绘，"信息"不再重影；其它窗口
  行为不变。
- **曾尝试并放弃的修法（勿再走）**：
  1. 挂钩 4 处 `RegisterClassA` 调用（0x414627 / 0x435396 / 0x4475AC / 0x44EB69 →
     跳板 0x406EDC），注册前给窗口类补 `CS_HREDRAW`（先对所有类、后改为仅 `TStatusBar`）
     ——两次都导致 SSP 启动后幽灵不显示、随后走进 SSP 自身的"卸载幽灵"路径并触发野
     WndProc 崩溃（与 9/24 记录的 SSP 偶发退出崩溃同款）。该环境对注册/退出等早期路径
     的挂钩极敏感，代码已从 `patch_dll.py` 移除。
  2. 挂 Todo/Notify 的 `FormResize`（0x463E78 / 0x464FC4，来自 DFM 方法表）在桩尾补
     `RedrawWindow(窗体 hwnd, 0, 0, 0x85)`——实测无效。
- **实现注意（踩过的坑）**：原指令是 6 字节 `FF 91 90 00 00 00`（`call [ecx+0x90]`），
  桩必须用 `call`（`E8 rel32` + 第 6 字节 `90` NOP）进入——**不能用 `jmp`**：`jmp` 不压
  返回地址，桩尾 `ret` 会弹栈上垃圾地址，导致所有控件创建流程错乱（表现为主菜单点任何
  选项都没反应）。

## 8. 退出/重载/人格切换修复（patch_exit_fix）

**现象**（都出自"卸载时序"这一条链）：

1. **退出崩溃**：WER 记录 `ssp.exe`、出错模块 `first.dll_unloaded`，故障偏移 `0x1476a`
   （也见过 `0x7474`）——卸载之后仍执行到已卸载模块的代码；随版本还可能表现为
   进程残留不退、时钟/文字残留、CPU 100% 自旋；
2. **重载 [SYSTEM]**：开发面板"显示错误日志"每次重载刷一条
   `SHIORI(unload) | Critical | [SYSTEM] Exception Raised at <值>`（故障地址 = DPI 上下文值一族）；
3. **尺寸类**：开着窗口退出后存档 ×1.5（150% 屏）；重载后 SSP 整体放大；
   切换到别的人格后，对方/SSP 新建的窗口整体放大。

**机制**：

- 退出流程：关精灵窗 → 经导出表调 unload（RVA `0xAA234`）→ 之后 SSP 才 `FreeLibrary`；
  卸载后残留的"僵尸活动"（窗口消息派发、收尾遗留调用）落到已卸载模块代码上 → 崩溃。
  断路必须落在"模块自身收尾/存档之后、卸载那一瞬之前"：过早破坏收尾（换 0x2E44 一族），
  过晚永远慢一步（`0x1476a` 就发生在卸载瞬间，轮询追不上）；
- 窗体尺寸/坐标的存档（保存函数 `0x462848`）按**调用线程的 DPI 上下文**输出：
  手动关窗走 request 包装（线程 `UNAWARE_GDISCALED(-5)`）→ 读到 96dpi 虚拟坐标（正确）；
  退出析构若跑在感知上下文 → 坐标被"提升"为物理像素（×1.5）。所以卸载全程
  （含 detach 期间**模块内部对 0xAA234 的直接调用**触发的"迟到存档"）线程必须保持 `-5`；
- 归还（恢复旧上下文）的时机还必须**不依赖"下一次加载谁"**：切人格时加载的是对方的
  SHIORI——任何挂在"本模块 load 路径"上的归还都不会运行 → 线程残留 `-5` →
  之后新建的窗口全部被 GDI 放大。

**定稿实现（全同步：无定时器/辅助线程/轮询；时序由调用序保证）**：

1. **unload 入口保持原始字节**；把 unload 导出经 EAT 重定向到存根 —— SSP 的调用进入
   存根，模块内部对 `0xAA234` 的直接调用仍走原函数（无需也不应接管）；
2. **存根**（`.cave+0x2400`）：开头先 `call` 收尾例程**清扫一轮**（防监控窗上残留的
   WndProc 桩被收尾消息打到，见第 10 节）→ 线程切 `UNAWARE_GDISCALED`（旧上下文写暂存槽 `.cave+0x23F4`，
   并 `SetPropA` 挂到 SSPMAIN 的 `"dpictx"` 属性）→ 双销毁注册窗体（Tnotifyform 槽
   `0x4B08CC`/VMT `0x464280`、Tfirstconfigform 槽 `0x4B298C`/VMT `0x468DC8`，RTTI 校验后调
   `TObject.Free` 跳板 `0x402E40`、槽清零；析构触发原生存档）→ `call` 原函数**完好入口**
   `0xAA234` 并等其返回 → 跳收尾；
3. **收尾例程**（`.cave+0x226A`）：只做 EnumWindows 断路（WndProc 落在
   [模块基址, +0x100000) 的窗口，**或类名为 `Tanalogclockform`/`Tcpuloadform` 的窗口**
   换成 `DefWindowProcA`）；**不做 DPI 恢复**——线程保持 `-5`；
4. **归还（V7）**：在 DllMain 的 `DLL_PROCESS_DETACH` 末尾（入口 detour）——原 DllMain
   执行完（此前的清理/迟到存档全部结束）后，从 `"dpictx"` 属性读回旧上下文归还，再交还
   loader。触发点 = "本模块自己的卸载"，与下一个加载者无关：**重载 / 切人格 / 退出全覆盖**。

**布局（.cave 固定偏移）**：

| 偏移 | 内容 |
|---|---|
| 0x226A | 收尾例程（只断路，不恢复） |
| 0x23F4 | 旧上下文暂存槽（存根写） |
| 0x2400 | 存根（先清扫一轮 + 切-5 + 存属性 + 双销毁 + call 完好入口 + 跳收尾） |
| 0x7500 | 枚举回调（断路：本模块范围 + 监控窗类名） |
| 0x7600 | 类名缓冲 |
| 0x7660/0x7680 | 类名串 `Tanalogclockform`/`Tcpuloadform` |
| 0x2600 | 窗口类名 `SSPMAIN-3145fdab-2ee0-4158-a1ce-832b553ad790` |
| 0x2630 | 属性名 `"dpictx"` |
| 0x2640 | V7 归还桩（DllMain detach detour） |
| 0x2700 | V7 入口跳板（原序言 6 字节 + 跳回入口+6） |

**实现要点**：

- DPI 切换复用 `.cave+0xB0` 的 `SetThreadDpiAwarenessContext` 指针槽（包装桩惰性解析；
  空槽 = 旧系统无该 API → 相关段整段跳过）；不要依赖弹窗/对话框行为做任何判断
  （本进程 MessageBoxA 被 SSP 改写）；
- 枚举回调取 hwnd 用 `[esp+0x24]`（pushad 后）；模块基址 = "回调自身地址 − 回调 RVA" 现算；
- V7 归还桩以"调用"方式执行原 DllMain（返回值经 pushad 槽还原给 loader），
  `reason == DLL_PROCESS_DETACH(0)` 才归还；归还序列只用 IAT/惰性解析的 API；
- 构建时脚本做：区域全零预检、入口/序言吻合校验、各段长度断言——不符直接报错拒出。

**验证（自动化）**：

- 重载 ×3：错误日志 0 条 [SYSTEM]；退出：WER=0、无崩溃弹窗、35 窗全关；
- 存档：模拟时钟 96×96 → **64×64**、文字信息窗 222 → **64×148**（= 逻辑值）；
- 重载前后开发面板矩形 (1414,81)-(1633,566) 逐像素一致；切人格来回无"整体放大"；
- 偶发"0x2E44 一族"（助手线程卸载期 Free 失效对象）为预存残余，与本层无关。

**部署与重建**：`python patch_dll.py "<ghost master 目录>"`（不带参数只写 `output/`）；
产物 = `output/first.dll`（仅复制它）；misaki.dll 保持原版不动、不再产出/部署。

## 9. 输入法修复（定稿：两门控 + 动态 DPI + 三重修复）

**现象**（仅 96dpi 虚拟化的 GDISCALED 窗口：骰子 / 打字游戏 / Todo / Notify 等；SSP 自有窗口不受影响）：

1. 候选框位置偏移（相对光标过远，首字母起即错；组字态因"回写回路"自正）；
2. 组字窗相对光标偏移、拖动时漂移；
3. 组字窗文字过小（系统 150% 缩放下仍按 100% 字号渲染）。

### 9.1 原理与前提

- **新旧微软拼音是两条管线**：旧版（msctfuimanager 体系）进程内 UI 直用原值，原本正确、且**不经**新版管线；新版（textinputframework + msctf）在进程内对输入控件查询感知级别，按判定"未感知应用"对锚点**再补一次 ×f** → 双重缩放。修复只落在新版专属路径，绝不碰共享源（CT 站点）。
- **坐标关系**：`屏幕矩形 = win + 客户矩形`（win = 输入框客户区左上角的屏幕坐标；客户矩形 = 光标/组字在框内的位置+尺寸，GDISCALED 下为逻辑值/虚拟单位）。正确值 = `win + f×客户矩形`（f = 系统 DPI/96）。凡"win 后面的那段"×f 即对。
- **MSCTF 内部关键结论（实测链）**：
  - 求界链（TIF 侧）：`GLB(tif+0x93510)` → 委托适配器（vtable `tif+0x5950`，槽位翻译层）→ `tif+0xAB8F0` → … → 存储对象 `ITextStoreACP::GetTextExt`；空态/组字矩形最终在 msctf 内成形。
  - **退化判断（空态 vs 组字态的天然分叉）**：msctf `case3(0x307B0)` 先经 `0x54850→0x548CF` 求范围矩形；随后按该矩形判定——**宽≤1 且高≤1（退化）→ 走"光标块"**（`GetGUIThreadInfo` 取 `rcCaret` 再 `MapWindowPoints(hwndCaret,NULL)`；该块是"store 未提供光标矩形"的兜底路径）；**非退化 → 直接用范围矩形**（组字态即走此路，物理正确）。实测骰子输入框的空态矩形为 12×12（非退化），故**不走光标块**。
  - **空态专属分支**：`[obj+0x98]==-1`（无组字）→ `call 0x5496E` 构建 `prc`（arg6 = prc 输出指针）——内部把"客户矩形（pt=obj+0x80/+0x84 + 光标尺寸）"与 `ClientToScreen([obj],(0,0))` 的 win 相加写出：`prc = win + 客户矩形`（未×f，故偏）。
  - 组字窗摆位链：`msctf+0x47510` 读位置对象（`+0x7C` 标志、`+0x80/0x84` 锚点 pt、`+0x88` 矩形）→ 站点 B `0x47749` 对 pt 调 `ClientToScreen` → 摆位；下游 `0x476FD` 附近有 `PtInRect` 门控——**其上游返回点勿改**（改了门控失配、组字窗消失）。
- **组字窗字体机制**：绘制每帧 `SelectObject(dc, [obj+0x18C]/[obj+0x194])` 选**缓存字体**；缓存仅由"字体设置事件"重建（每键的 `ImmGetCompositionFontW` 只喂布局测量，不喂绘制）→ 字号放大必须落在"SelectObject 替换字体"处（每帧生效）；尺寸测量用同一缓存对象，匹配需按"对象==缓存源句柄"。
- **基线微偏**：组字窗摆位对齐用"应用上报的光标行"（旧字号语义），放大字号渲染后相对基线略高（≈半个小写字母），判定为可接受残差，不补偿。

### 9.3 三重修复（实现）

- **两门控（三重修复共用）**：
  ① 宿主级（安装时）：`shcore!GetProcessDpiAwareness(当前进程)` == `UNAWARE(0)`（原版 MATERIA 等 unaware 宿主，其 IME 由系统原生正确处理）→ **整层 no-op**（不装任何钩）；仅 aware 宿主（SSP = 2）生效。实测两类宿主的打字输入框窗口级都是 GDISCALED/96dpi（无法区分）→ 必须以**进程级**为判别。
  ② 窗口级（运行时）：相关窗口 `GetDpiForWindow()==96` 才缩放（仅 GDISCALED 窗口；SSP 普通窗口不修）。
- **动态因子 f（实时跟随切档）**：GDISCALED 线程里 `GetDpiForSystem`/`GetDeviceCaps` 均失真（恒 96）；取因子时把线程**临时尖峰 PMv2**（`SetThreadDpiAwarenessContext(-4)`）→ `GetDpiForMonitor(MonitorFromPoint((0,0),MONITOR_DEFAULTTONEAREST), MDT_EFFECTIVE_DPI)` → 恢复原上下文；`f = 系统DPI/96`（每次现算，无定时器、无轮询）。96dpi 时 f=1 全恒等。刷新由钩1触发（CT 站点观察），三重修复共用。
- **修复① 候选框空态位置 + 感知修正**：
  - 位置：钩 `msctf+0x5495C`（空态分支 call 处，原 `E8 0D 00 00 00`）。流程：门控（宿主/`[ecx]`/DPI）→ 调原函数（prc 填好）→ `prc' = win + f×(prc−win)`（win = `ClientToScreen([obj],(0,0))` 现算，与 callee 同句柄）→ 跳回原 call 下一条。
  - 感知：钩 `user32!GetWindowDpiAwarenessContext`（独立子层，链入 load/unload）；返回地址 ∈ `tif+{0x93642,0x9365C}` 时回答安装时取得的 **PMv2 规范句柄** → 新版管线不再补第二次 ×f。版本护栏：站点失配自动降级直通（功能静默失效、无副作用）。
- **修复② 组字窗位置**：钩 `msctf+0x47749`（摆位锚点 → ClientToScreen 前）：pt ×f → 走原 ClientToScreen（win 现算）→ **拖动自动跟随**；组字态经"回写回路"自动正确（**故 rectB 组字态绝不能再加变换**）。
- **修复③ 组字窗字号**：钩 `gdi32!SelectObject` 入口：返回地址 ∈ 字体四点 **或** 对象==缓存源句柄（任意调用者）→ 替换为按 f 重建的字体（`GetObjectW→lfHeight/lfWidth×f→CreateFontIndirectW`，两句柄缓存、惰性创建）；桩顶先"因子刷新 + 缓存对账"（因子变化清空缓存，否则切档后仍选同一原句柄会复用旧字号）。同一 DPI 门控。
- **装配与还原安全**：`load` 导出经 EAT 重定向到"载入包装"（call 安装例程后转原包装）；`unload` 同理先还原再转。目标函数经 `GetModuleHandleA/GetProcAddress`（first.dll IAT 槽 `0x4B31E4/0x4B31E0`）于安装时解析；`VirtualProtect` 写 E9、还原以首字节==E9 判定。**所有被改站点在安装时保存"运行时原字节"，卸载写回保存值（含重定位 dword）——绝不写死文件字节**（曾写死首选基址字节 `FF 15 18 50 10 10`，还原后站点指向未映射地址，开着骰子窗退出即崩）。`GetDpiForMonitor` 属 shcore.dll：GMH 未加载则 `LoadLibraryA` 兜底。
- **落位原则**：只钩"新版引擎专属、且在目标值产生之前的读取/构建点"；不碰共享源（CT）、不做空态/组字态判断（两态分支天然隔离）、不写死运行时字节。

### 9.4 历史与排障存档

- **栈平衡教训**：钩内联调用 API 必须按约定核算 push/pop——stdcall 由被调方清参数，调用方不可再 pop（曾因此安装例程净差 +4B、`popal` 错位、加载即崩，现象 `Exception Raised at 00000000 (Writing 00000000)`）。
- **槽位越界事故（2026-09-29）**：安装例程加长越过还原例程起点 1 字节，末尾 `ret` 被覆盖 → 每次 load 执行跌落进还原例程、刚装的钩子立即被还原（任何会话都不生效）。已对全部相邻槽位加**构建期长度断言**，越界即报错。
- **曾试验未采用**：ImmGetCompositionFontW 入口缩放钩（窗口自适应已被修复③覆盖）；ImmSetCompositionFont 反复重设（需触发、有延迟，废弃）。
- **旧方案存档（均已移除）**：CT 站点直接 ÷f（破坏旧引擎）；`msctf+0x47A8A` SetWindowPos 补偿 `x'=O+f(x−O)`（O 死值 → 拖动漂移；且组字态随回路二次缩放）；空态曾在"光标块"（GetGUIThreadInfo 兜底）挂钩——误判（实测空态矩形非退化、该块被跳过），正确落点为 `0x5495C`。

## 10. 缩放跨 100% 边界的分层表面重置修复（first.dll：上屏桩重挂子类化 + cloak）

**现象**：

- 显示缩放**向上**跨过 100%（如 100%→125%/150%，或 150%→100%→150%）后：窗口边框/位置
  正常，但**窗内内容整体缩小**（约 0.75×）且**不再自行恢复**；模拟时钟、CPU 信息窗均中招；
  向下切回 100% 则正常；其他比例之间互切正常。
- 仅在 GDISCALED（"系统(增强)"）宿主 + 逐像素 alpha（UpdateLayeredWindow）窗上出现。

**机制（实证）**：

- 系统在缩放跨过 100%（恒等点）时对**每个窗口**做一次"虚拟→物理映射"重建；两个监控窗
  按顺序处理（时钟先、信息窗后——即早期观察到的"时钟先动、信息窗后动"）；
- 该重建对普通窗口无碍，但对 GDISCALED 的**应用自供表面**（ULW）会留下错误的缩放状态：
  100%→上切后映射停留在恒等（内容按 100% 尺寸画进已放大的物理矩形）；
- **blit（ULW）不触发映射重算**：时钟每秒重绘也一直坏；只有**重建层状态**
  （`WS_EX_LAYERED` 去/加往返）能强制重算 → 内容立即恢复；
- 系统对两窗的重置是逐窗顺序的，且**信息窗的重置晚于时钟**——这是下面刷新时序设计的依据。

**定稿实现（全部在 first.dll；misaki 零修改）**：

1. **子类化自持**：ULW 上屏桩每帧对两窗各做一次 `GetWindowLongA(hwnd, GWL_WNDPROC)`；
   当前过程不是本模块 WndProc 桩（首次 / 被应用自身重设 / 窗口重建）→ 记录旧过程 +
   `SetWindowLongA` 重挂；
2. **WndProc 桩**：`WM_WINDOWPOSCHANGED(0x47)` 时采样本窗**物理宽**：线程临时尖峰 PMv2
   （`SetThreadDpiAwarenessContext(-4)`，指针槽由上屏桩预先解析）→ `GetWindowRect` →
   **流程尾部**恢复原上下文；窗口索引由 hwnd 与已装句柄槽比对（0=时钟 1=信息），
   非 0x47 消息也要先定索引再尾跳旧过程；
3. **门控**："上次 ≤ 本窗层宽（64/148）→ 本次 > 本窗层宽"（即向上穿越 100%）才动作；
   **先存 LASTW 再动作**（防重入）；另有 **ARMED 校准位**：每窗在"首次进入放大态（宽 > 层宽）"
   之前只记录宽度、绝不触发——避免启动期窗口未长全（首采小宽度）造成的假穿越误刷新；
4. 动作 = cloak 本窗（`DwmSetWindowAttribute(DWMWA_CLOAK=13, TRUE)`；dwmapi 懒解析：
   `GetModuleHandleA` 失败则经 `kernel32!LoadLibraryA` 兜底——旧 unaware 宿主（如 MATERIA）
   可能尚未加载 dwmapi）→ `WS_EX_LAYERED` 去/加往返 → 置"待解除"标记；
5. **解除 cloak**：由该窗**下一次 ULW 上屏桩**在尾跳前完成（此时内容已重绘）→
   "销毁→重绘"空窗全程不可见；
6. **卸载清扫**（EXITFIX，与第 8 节同源）：枚举回调按"本模块范围 + 监控窗类名"把残留
   WndProc 换成 `DefWindowProcA`（不依赖等于哪个桩，死桩也能清）；unload 存根开头先跑
   一轮清扫，确保收尾消息不会打到死桩上。子类化与清扫必须成对部署。

**为什么"两窗各自子类化、各自即时刷新"**：

- 系统重置逐窗顺序（时钟先、信息窗后）：若只在时钟事件里顺手刷两窗，信息窗的刷新会在
  它自己被重置**之前**发生 → 随后又被重置坏（已复现）；各自在自己事件里刷新才与
  各自的重置时刻对齐。
- 曾以"仅时钟子类 + PEND 延迟刷信息窗"作为过渡验证可行；最终采用双窗独立子类
  （更简洁、信息窗即时恢复）。

**布局（first.dll .cave，固定偏移）**：

| 偏移 | 内容 |
|---|---|
| 0x7700 | ULW 上屏桩（掩码 + 子类化安装/重挂 + 解除 cloak；≤0x360） |
| 0x7A60/0x7A64 | 旧 WndProc 槽（时钟/信息）[idx*4] |
| 0x7A68/0x7A6C | 上次物理宽（穿越判定）[idx*4] |
| 0x7A70/0x7A74 | 已装窗口句柄 [idx*4] |
| 0x7A78 | `DwmSetWindowAttribute` 指针（懒解析） |
| 0x7A7C | `LoadLibraryA` 指针（懒解析兜底） |
| 0x7A80 | 样式暂存（WndProc） |
| 0x7A84/0x7A88 | cloak BOOL / 解除 cloak BOOL（两线程分用，避免互踩） |

`0x2400` 卸载存根（开头先 `call` 收尾例程清扫一轮）。

**要点与教训**：

- **非 0x47 消息直跳尾部的路径也要有索引**：窗口索引必须在消息判定**之前**设定，
  否则尾跳旧过程会用垃圾索引读错槽（曾实测崩溃：`first.dll` 范围内 AV，指令 =
  尾跳前 `mov eax,[ebx+edi*4-0xA8]`，edi 为垃圾）；
- **恢复 DPI 上下文的调用会清 EAX**——宽度必须在"门控 + 存 LASTW"全部完成后才恢复；
  曾把恢复提前到测量之后，导致存入槽的是线程旧上下文句柄（真实句柄值 0x22=34），
  门控永远"只校准不触发"；
- **ULW 模块的 IAT 常量是绝对 VA**（`ULWFIX_IAT_* = 0x4Bxxxx`），误当 RVA 再加 `0x400000`
  → 首次触发 DWM 解析即读未映射地址 AV（伪穿越端到端测试暴露）；与 `_EXF_IAT_*`（RVA）
  属两套约定，改动前先看常量注释；
- WndProc 桩必须保护 `EBX/ESI/EDI`、PIC 基址 = push×3 后 `call$+5` 返回值（+8）、尾跳旧过程；
  stdcall API 由被调方清参（不可手动 `add esp`）；
- **只挂子类 = 退出必崩**：卸载后桩成死指针，收尾消息打到即 AV（WER 里先见
  `first.dll_unloaded` 一族，后见死桩地址）。**子类化与卸载清扫必须成对部署**；
- 曾试"misaki 入口 detach 钩子自清"（含 EnumWindows/类名多版、文件探针取证），均未可靠生效；
  最终改由 first.dll 卸载清扫承载（该路径已被第 8 节证明必然执行）；
- 构建期防守：桩区/字符串/槽位的**布局重叠检查**、长度断言、`.cave` 非零预检——
  曾发生"槽位压在字符串上"（`SetThreadDpiAwarenessContext` 串中的 "enes" 被当作函数指针）
  与"字符串少写 1 字节导致后续全部右移"两类事故，均由构建检查拦截；
- 启动期"假穿越"：首采若落在窗口未长全的小宽度（≤层宽），下一次正常宽度即构成
  "≤→>" 误触发（MATERIA 实测到启动后自动刷新一次）。ARMED 校准位根治；
- **常量混用 RVA/VA 事故（旧版）**：`LoadLibraryA` 的 IAT 常量曾误写为 RVA（缺 `0x400000`），
  造成 `call [错位址]` 读到 0 → **MATERIA（未加载 dwmapi、走兜底）在 WndProc 内 EIP=0
  崩溃**；SSP 因 dwmapi 已加载、从不走该分支而完好。由转储精确定位（桩内 +0xDC）。

**验证**：

- **迁移版·本机自动化**（伪穿越：把该窗 LASTW 手动置为层宽 + 移动窗口）：启动采样
  96/222 且双窗 ARMED=1；触发后 `DwmSetWindowAttribute` 解析、cloak 调用、
  `WS_EX_LAYERED` 往返、下一帧自动解除，全程无崩溃；hitvis 掩码红=0；
- **旧实现（misaki 侧）用户实测存档**：150↔100 来回两窗**即时**恢复、无缩小、
  **无黑闪**（cloak 生效）；125↔150 等常规切换无动静、无闪烁；拖动/打字正常；
  重载/切人格/退出无崩溃；**MATERIA（旧 unaware 宿主）**跨 100% 恢复、无闪、不崩
  （dwmapi 兜底 + ARMED 验证）；
- 迁移版真机跨屏回归以用户实测为准。

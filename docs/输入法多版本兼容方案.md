## 3. 切换崩溃：AWRFIX 槽重叠（已修复）

- `AWRFIX_ORIG=0x104`（8B）与 `AWRFIX_T5=0x108`（4B）重叠；安装顺序"先存 8B、再写 T5"
  覆盖保存的第 5 字节；卸载还原出 `8B FF 55 8B <低字节>`。本次 +3 处成
  `mov edx,[0x180D8B64]`。
- 修复：`AWRFIX_ORIG` 移至 **0x128**（独立 8B）；`emit_hook`/`build_ime_layer` 增加
  "保存区不得与 T5 重叠"断言；《窗口分析及修复.md》§9.4 记录。

## 5. 已实现的运行时解析（cave+0x4E60，0x6A8B）

### 5.1 入口与数据

- 安装例程（cave+0x3300）在 API/msctf 解析、宿主门控之后：
  `lea esi,[ebx+data_va]; call cave+0x4E60`；解析例程 `pushad` 保存全部寄存器，
  结束时 `popad; ret`，不破坏安装流程。
- 解析例程自己从 msctf PE 头取 `SizeOfImage`：
  `end = base + [base + e_lfanew + 0x50]`，写入 `IME_MSCTF_END`。
- 新增数据槽（cave 内偏移，均在 0x2810-0x2A00 数据区）：
  | 槽 | 偏移 | 含义 |
  |---|---|---|
  | IME_CW_SITE | 0x198 | CW 站点 VA（0=未解析） |
  | IME_CW_SLOT | 0x19C | 该站点 ClientToScreen IAT 槽 VA |
  | IME_CW_RET | 0x1A0 | CW 桩跳回地址（site+6） |
  | IME_CARET_SITE | 0x1A4 | 空态站点 VA（0=未解析） |
  | IME_MSCTF_END | 0x1A8 | msctf 映像末 |
  | IME_FONT_OK | 0x1AC | 字体四点已解析（u8） |
  | IME_FONT_TMP | 0x1B0 | 四点临时返回地址（4×dword；扫描用） |
  | IME_SCAN_* | 0x1C0-0x1D3 | 扫描工作槽 |
  | AWRFIX_TIB_END | 0x130 | TIF 映像末（AWRFIX 数据区） |

### 5.2 纯匹配 / 纯扫描（无旧新地址）

- **CW / Caret**：已删除旧/新 RVA 快路径；解析例程只跑 §5.3 的结构扫描。
  当前 9549 实测扫描命中 `0x476D9` / `0x548BC`；合成旧版映像也命中
  `0x47749` / `0x5495C`。
- **字体（纯匹配）**：SEL 桩每次被调用时现场检查当前 SelectObject 调用点：
  1. 调用点必须是 `FF 15`（call [slot]）；
  2. 前 0x30 字节内必须出现字段压参 `FF B0-B7 8C/94 01 00 00`
     （`push [reg+0x18C/0x194]`）。
  命中 → 视为组字字体选择，按 f 替换；**不使用任何旧/新版本地址或静态返回地址表**。
  没有字段压参的调用（恢复/UI）只在该对象等于已缓存的组字源句柄时才替换。
- 所有匹配都是**运行时结构验证**；构建机无需安装对应 Windows。

### 5.3 结构扫描（唯一路径，无地址兜底）

- **CW**：逐字节扫描 `FF 15` + 前 5B `8B 46 04 FF 30` + 槽值 `==ClientToScreen`；
  唯一结构命中才采用（当前 msctf 中该前缀仅 CW 站点点）。
- **Caret**：扫描 `E8 0D 00 00 00` + callee 序言 + 前 7B 压参骨架；唯一命中才采用。
- **字体**：SEL 桩逐调用做字段压参匹配（见 5.2），无返回地址表/四点扫描。
  静态分析里的 0xE388C 四连簇与旧四点仅作为历史调查结论保留，不参与运行。
- 扫描上界 = `end-0x20`（读安全余量）；槽范围仍用真 `IME_MSCTF_END`；任何一项
  0/多命中、越界、校验失败 → 对应修复不安装。

### 5.4 安装/还原接线

- CW 钩：安装例程从 `IME_CW_SITE` 读站点；CW 桩不再写死 IAT 槽/返回地址，改为
  `mov ecx,[IME_CW_SLOT]; call [ecx]`、`mov edx,[IME_CW_RET]; jmp edx`。
- Caret 钩：从 `IME_CARET_SITE` 读站点；TGT/RET 由解析例程写入（不再由安装例程
  写死 +0x12/+5）。
- 字体 SEL 钩：gdi32!SelectObject 解析成功即安装；匹配完全由桩内字段压参扫描决定，
  不再依赖解析例程的字体四点/FONT_OK。C1-C4 仅保留为历史/兼容数据。
- 还原例程同样从站点槽读取（不再用固定 RVA）；保存/还原的仍是**安装时的运行时原字节**。
- AWRFIX 钩：仍由独立子层链在 IME 安装之后；逻辑改为版本无关门控（见 5.5）。

### 5.4b 字体 DPI 门控（最终）

- 字段压参命中后，SEL 桩按以下顺序取窗口：
  1. `WindowFromDC(hdc)`（普通窗口 DC 直接得到组字窗口）；
  2. **CW 钩记录的焦点窗** `IME_LAST_HWND`（组字绘制常用内存 DC，`WindowFromDC`
     返回 0；CW 桩在焦点窗 96dpi 时记录）；
  3. `GetFocus()`（最后兜底）。
- 任一窗口 `GetDpiForWindow()==96` 才替换字体；否则直通。
- 历史事故（已废弃的静态表方案）：表循环未命中时误用了带标志位的条件跳转，循环
  退出后全部落入“命中”分支 → 所有 SelectObject 都被放大；以及把恢复点入表 →
  恢复的 UI 字体被放大。最终改为纯字段压参匹配后，两类误放大都从结构上消除。

### 5.5 AWRFIX：TIF 映像范围 + 输入窗 96dpi 门控（纯版本）

- 不再比对 `tif+0x93642/0x9365C/0x94DC2/0x94DDC/0x95276` 等任何固定返回地址
  （已用字节搜索确认：部署版 AWRFIX 桩中这些 RVA 出现次数均为 0）。
- 桩内懒解析 TIF 基址并解析 `SizeOfImage`；返回地址在 `[tib, tib+size)` 内才进入判断。
- 门控顺序：
  1. 调原函数取真实上下文，默认返回该值；
  2. 若上下文为 `GDISCALED(-5)`/`UNAWARE(-1)`，检查 TIF 传入 hwnd 的
     `GetDpiForWindow()==96` → 返回 PMv2；
  3. **无论上下文是什么**，再检查 CW 钩记录的 96dpi 组字输入窗
     `IME_LAST_HWND` 的 `GetDpiForWindow()==96` → 返回 PMv2；
  4. 都不满足 → 原样返回。
- **为什么之前纯门控失效**：TIF 查询传入的 hwnd 不一定是 GDISCALED 输入窗
  （可能是文档/顶层窗），原逻辑要求它本身 `-5/-1 + 96dpi`，不满足就直接返回真值，
  从未尝试组字输入窗；同时 CW 桩早期在 96dpi 检查**之前**记录 `IME_LAST_HWND`，
  可能存入 144dpi 主窗。现已改为“仅 96dpi 通过后记录”，并在门控中无条件尝试该输入窗。
- 非 TIF 调用者仍全直通；依赖 `IME_PTR_GDPI`（user32!GetDpiForWindow）。

### 5.6 CTS 因子刷新：msctf 映像范围

- 钩1（user32!ClientToScreen）不再比对 CT1/2/3 固定返回地址；返回地址落在
  `[msctf_base, msctf_end)` 内即视为 msctf 调用，再按焦点窗 96dpi 门控刷新因子。
- 版本无关；代价是 msctf 每次 ClientToScreen 多一次 GetFocus/GetDpiForWindow，
  仅在 96dpi 焦点窗口时刷新，可接受。

## 8. 边界与失败策略

- 全部站点由结构扫描/纯匹配覆盖，**没有旧/新地址快路径**。
- 若微软重写函数导致签名失配：对应修复 no-op（不崩溃），不会退回"猜地址"。
- 字体匹配不再依赖 4 连簇/返回地址表，而是逐调用检查字段压参；若未来字段偏移
  或调用形式改变，字体修复会 no-op；位置/感知修复不受影响。
- AWRFIX 的映像范围+96dpi 输入窗门控不依赖任何内部偏移，抗更新能力最强。
- 旧版 CW/Caret 布局已用合成映像验证纯扫描可命中；真实旧系统仍建议 VM 全量回归。

  跳板 0x5A00、安装 0x5A20；CW 桩 0x5E80；空态桩 0x7000；安装 0x3300；还原 0x6000。
- 数据槽：CW/Caret/END + `IME_LAST_HWND=0x1E4`；AWRFIX_TIB_END=0x130。
- 构建：`python patch_dll.py`（不部署）或 `python patch_dll.py "<ghost master 目录>"`。

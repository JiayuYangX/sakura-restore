# first.dll 链接补丁与自动加链接说明

> 本文档记录 first.dll 的「自动加链接」机制，以及我们给汉化版加的两个链接相关补丁。
> 菜单/双击/搜索框/小游戏相关分析与补丁见《菜单逻辑分析及补丁.md》。
> 地址约定：**文件偏移 = VA − 0x400C00**（CODE 段；反向即 VA = 文件偏移 + 0x400C00）。
> 所有补丁集成在 `patch_dll.py`，可从 input/first.dll 一键重建。

---

## 1. first.dll 的「自动加链接」机制（原始行为）

### 1.1 表现

显示对话文本时，ghost 会把文本中出现的特定人名替换成 **SSTP 锚点**：

```text
\_a[名字]名字\_a
```

SSP 会把它渲染成绿色可点击链接（气球配置 anchor.font.color = RGB(0,192,0)）。
点击后 SSP 发送 `OnAnchorSelect` 事件，ghost 再用对应的回应脚本作答。

### 1.2 注册代码（装载时执行）

在 VA 0x4AA9E9 ～ 0x4AAA3C 连续 7 段（每段 12 字节）：

```asm
push ebp                  ; 让被调函数经 [ebp+8] 找到调用方的列表对象
mov eax, <名字常量指针>
call 0x4AA838             ; 构建 \_a[名]名\_a 并加入名单
pop ecx
```

### 1.3 名字常量表

Delphi 常量字符串格式（8 字节头 + 文本）：`FF FF FF FF <长度:4> <文本>`；
**原版为 Shift_JIS，汉化版同一槽位被 translated.csv 写成 GBK**。

| # | 数据文件偏移 | 常量指针 VA | 原版文本 | 汉化后 |
|---|---|---|---|---|
| 1 | 0xAA0BC | 0x4AACBC | いたる | 樋上至 |
| 2 | 0xAA0CC | 0x4AACCC | ガッツ石松 | 石松葛兹 |
| 3 | 0xAA0E0 | 0x4AACE0 | AIBO | AIBO |
| 4 | 0xAA0F0 | 0x4AACF0 | VAIO | VAIO |
| 5 | 0xAA100 | 0x4AAD00 | あかほり | 赤崛悟 |
| 6 | 0xAA114 | 0x4AAD14 | ラグナロク | 仙境传说 |
| 7 | 0xAA128 | 0x4AAD28 | 木野さん | 木野薰 |

表后紧接代码（0xAA134 起）。

### 1.4 构建与注册函数

- `0x4AA838`：用 RTL 变参拼接 `0x403F00` 把下列片段拼成 `\_a[名]名\_a`，再调用
  `0x417C90` 加入名单（名单对象在调用方栈帧 [ebp-4]，这正是每段前面要 `push ebp` 的原因）：
  - `0x4AA8C0` = `\_a[`（文件 0xA9CC0）
  - `0x4AA8D0` = `]`（文件 0xA9CD0）
  - `0x4AA8DC` = `\_a`（文件 0xA9CDC）

### 1.5 点击后的处理（OnAnchorSelect）

处理链在 VA 0x47A0E7 ～ 0x47A1DB：把 Ref0（[ebp-0x1c]）与名字常量逐个比较：

| 名字（常量位置） | 命中后的回应脚本常量 |
|---|---|
| 樋上至（文件 0x7DF3C，比较处于链的更早位置） | — |
| 木野薰（0x4873E8 / 文件 0x867E8） | 0x4873FC |
| 石松葛兹（0x487434 / 0x86834） | 0x487448 |
| AIBO（0x48749C / 0x8689C） | 0x4874AC |
| VAIO（0x487500 / 0x86900） | 0x487510 |
| 赤崛悟（0x48758C / 0x8698C） | 0x47FAA8 |
| 仙境传说（0x4875A0 / 0x869A0） | 0x4875B4 |
| 海原雄山（0x4875E0 / 0x869E0） | 0x4875F4 |

全不匹配 → 兜底脚本 `\0\s0……\w8\w8\s4ん？`（常量 0x48769C / 文件 0x86A9C；
汉化版此串已被 translated.csv 改成 `\0\s0哎呀\w8\w8\s4嗯？`）。

> **关键维护点**：加链接名单（1.3）和点击处理表（1.5）是**两套独立数据**，同名必须一致
> （汉化后都要是中文）。历史上出现过「名单里是 木野熏、处理表里是 木野薰」导致点击失效的问题。

## 2. 补丁一：海原雄山加入自动加链接名单

- **问题**：海原雄山只存在于点击处理表（1.5），不在加链接名单（1.3）里 → 永远不是链接。
- **难点**：注册序列 7 段背靠背，后面紧接代码，没有空位插第 8 段。
- **做法**（`patch_dll.py` 自动完成）：
  1. 新增可执行节 `.cave`；
  2. 把第 7 段（木野さん）的 `call 0x4AA838`（**文件 0xA9E37**，VA 0x4AAA37，
     原字节 `E8 FC FD FF FF`）重定向到 26 字节桩（`.cave+0x00`）；
  3. 桩内：先按原样补一次注册（进入时 EAX=木野さん，由原调用方设好）→ 用
     `call $+5 / pop eax / add eax, <相对量>` 位置无关地取得**已有的海原雄山常量**
     （0x4875E0，即 1.5 表里那个，已被翻译成 GBK）→ 再调 `0x4AA838` 注册 → `ret`。
- **效果**：海原雄山进入加链接名单；不新增字符串、不影响原 7 个；位置无关，不怕重定位。

## 3. 补丁二：RSS 头条链接点击打开浏览器

- **背景**：SSP 的 HEADLINE 功能把 `##[headlinedata]##` 展开成一串
  `\_a[URL]标题\_a` 锚点；点击后 SSP 先发 `OnAnchorSelectEx`（ghost 回 204），
  再发 `OnAnchorSelect`（Ref0 = 文章 URL）。
- **原问题**：URL 不在名字表里 → 命中兜底「……ん？」→ SSP 认为事件已处理，
  **不会**打开浏览器。
- **做法**：
  1. 把兜底分支入口（**文件 0x795CE**，VA 0x47A1CE，原字节
     `8D 45 E4 BA 9C 76 48 00` = `lea eax,[ebp-0x1c] / mov edx,0x48769C`）
     改成 `jmp 桩2` + 3 个 NOP；
  2. 桩2（`.cave+0x20`，134 字节，位置无关）：
     - 保存 ebx/esi/edi，取自身地址作基址；
     - Ref0（[ebp-0x1c]）为空 / 不以 `http` 开头 / 长度 > 256 → 复刻原兜底，行为不变；
     - 否则在节内缓冲拼出 **`\![open,browser,<URL>]`**：
       前缀常量在 `.cave+0x100`；缓冲头 `refcnt=-1、length=URL长+17`，
       数据 = 前缀 + URL + `]` + `\0`；
     - 把缓冲指针写回 [ebp-0x1c]，跳到公共出口 0x47A399 → SSP 执行脚本打开浏览器。
- **边界**：上限 256 字符；非 http 锚点（如自定义 `\_a[id]`）仍走原逻辑（不影响其它功能）。

## 4. `.cave` 节布局（链接补丁部分）

| 节内偏移 | 内容 |
|---|---|
| 0x000 | 桩1：海原雄山注册（26 字节） |
| 0x020 | 桩2：OnAnchorSelect http 打开（134 字节） |
| 0x100 | 常量 `\![open,browser,`（16 字节） |
| 0x1F8–0x3FF | 桩2 响应缓冲（string 头 + 数据） |
| 其余 | 菜单/游戏补丁用（见《菜单逻辑分析及补丁.md》）与预留 |

- 节属性：CODE|EXECUTE|READ|WRITE；追加在文件末尾（RVA 0xE2000，文件 0xD9800）。
- patch_dll.py 会自动更新节表、SizeOfImage，并逐字节校验每个补丁点的原始字节。
- 所有桩均为**位置无关代码**（只用相对跳转/调用 + 自定位取址）。
  SSP 自己占着首选基址 0x400000，本 DLL 每次都会被重定位，绝对地址不可用。

## 5. 构建与部署

```text
python patch_dll.py                          # 生成 output/first.dll
python patch_dll.py "C:\...\SSP\ghost\first\ghost\master\first.dll"   # 生成并部署
```

执行顺序：translated.csv 字符串 → 兼容补丁（NOTIFY/诱导模式）→
链接补丁（本章）与菜单/游戏补丁（《菜单逻辑分析及补丁.md》）→ AITXT 词库。
部署需先关 SSP（文件被锁）。

**维护提醒**：
- 改人名时，1.3（加链接名单）与 1.5（点击处理表）两处都要改（translated.csv 对应槽位）；
- 海原雄山复用的是 1.5 表里的常量（0x4875E0），改中文时它会自动跟着变。

---

## 6. 验证方法（无游戏环境）

- 用 capstone 反汇编 `.cave` 链接补丁的两个桩与两处钩子，核对 rel32/偏移；
- 两处钩子：
  - 0xA9E37 → `.cave+0x00`（海原雄山）
  - 0x795CE → `.cave+0x20`（RSS 链接）
- 对比改动前后文件：除 `.cave`、钩子点、AITXT、字符串槽位外不应有其它差异。
